# Blackjack Trainer

An **offline, config-driven blackjack game** built as an installable PWA, optimized
for mobile (Android Chrome; iOS Safari supported). Personal learning tool — chips
only, no real money. The full vision and phase plan live in
[`blackjack-trainer-spec.md`](blackjack-trainer-spec.md).

**Status: Phases 1–5 complete** — a correct, unit-tested game of blackjack with a
mobile-first UI, SVG cards & chips, animations, synthesized sound, saved progress,
a **computed basic-strategy advisor** (tap-to-reveal hints with explanations), a
**live Hi-Lo card-counting readout** as the shoe depletes, and a **Monte Carlo
betting-system simulator** that charts thousands of sessions. Only Phase 6 (hosting +
real-device install) remains (see [Roadmap](#roadmap)).

## Quick start

Requires **Node 18+** (built with Node 24 LTS) and npm.

```bash
npm install
npm run dev        # play at http://localhost:5173
npm test           # run the engine unit tests
npm run build      # production build (PWA: manifest + service worker) -> dist/
npm run preview    # serve the production build at http://localhost:4173
npm run icons      # regenerate the placeholder app icons
```

## Changing the rules

**All blackjack rules live in one file: [`config/blackjack-rules.config.js`](config/blackjack-rules.config.js).**
It is the single source of truth — the engine reads from it and never hardcodes a
rule. Edit a value and:

- in **dev** (`npm run dev`), Vite hot-reloads instantly;
- for a **built/installed** app, the config is bundled, so run `npm run build` again.

Common knobs: number of decks, dealer **H17/S17** (`hitsSoft17`), blackjack payout
**3:2 vs 6:5** (`payouts.blackjack`), table **min/max bet**, starting bankroll, and
chip denominations.

### What the game implements

Dealing, hit / stand / **double** / **split** (including split-aces one-card and
double-after-split), **late surrender**, **insurance**, dealer play with US
**peek**, blackjack/bust/push detection, 3:2 (or 6:5) payouts, chip betting, and
bankroll tracking.

Plus a **basic-strategy advisor** (tap *💡 Show basic-strategy hint* during your
turn): it recommends the optimal move with a plain-language why and flags it when
you deviate. See [Strategy hints](#strategy-hints) for how it's derived.

Plus a **live Hi-Lo count** (running + true count, with decks remaining) shown under
the top bar — it updates as cards appear and counts the dealer's hole card only once
it's revealed. See [Card counting](#card-counting).

The following config options are **not implemented yet**. The app runs a capability
guard at startup and **warns in the console (and on-screen) if you enable any of
them**, rather than silently mis-playing:

| Config option | Status |
| --- | --- |
| `player.surrender: 'early'` | falls back to late surrender |
| `shoe.continuousShuffle` | falls back to penetration-based reshuffle |
| `dealer.peeksForBlackjack: false` (European) | falls back to US peek |
| `player.resplitAces`, `player.hitSplitAces` | split aces always get one card |

The **bankroll and mute setting persist** across sessions via IndexedDB (an
interrupted hand is voided, not charged, on reload). Use the topbar **↺** to reset
to the starting bankroll.

## Project layout

```
config/   blackjack-rules.config.js   the single source of truth for the rules
src/
  engine/      pure, unit-tested game logic — no DOM:
               cards · shoe (Fisher-Yates) · hand · dealer · settlement ·
               game (state machine) · money (integer cents) · validateRules (guard)
  assets/      the swappable look + sound: theme.js (palette) · svg.js (cards/chips)
               · sound.js (Web Audio effects)
  persistence/ store.js (tiny IndexedDB key/value) · persist.js (bankroll + settings)
  teaching/    computed basic strategy: probabilities · dealer-odds · ev · advisor · explain
  ui/          DOM rendering (render.js) + input/audio wiring (controls.js)
  main.js      bootstrap: config -> guard -> load -> game -> mount
tests/     vitest engine tests (one file per module)
scripts/   generate-icons.mjs — placeholder icon generator
public/icons/  app icons (simple placeholders)
```

The engine is **pure and rules-injected** (functions take the rules object), so it
is deterministic and testable across rule variants. The UI asks the engine for
action legality (`canHit`/`canDouble`/`canSplit`) and never re-derives rules.

## Changing art & sounds

The look and sound live in **`src/assets/`** so they're easy to re-skin in one
place: `theme.js` (suit colors, card + chip palette), `svg.js` (the programmatic
card / chip art), and `sound.js` (the synthesized Web Audio effects). App icons are
generated by `scripts/generate-icons.mjs` into `public/icons/` (`npm run icons`).
Animations respect `prefers-reduced-motion`, and sound has an in-app mute toggle.

## Strategy hints

The advisor is **computed from your configured rules**, not recalled from a chart:
it builds the dealer's outcome distribution for the upcard (respecting H17/S17 and
the peek), then compares the expected value of standing, hitting, doubling,
splitting, and surrendering and recommends the highest. So it adapts to H17/S17,
DAS, surrender, and the double restriction. It lives in [`src/teaching/`](src/teaching).

It is validated cell-by-cell against the canonical 6-deck S17 DAS chart in the tests
(hard, soft, pairs, surrender, and H17/S17/DAS sensitivity). Two honest caveats:

- The closest decisions (e.g. **A,2 vs 5**) sit within ~0.01 EV; the infinite-deck
  model may pick the opposite of a given chart on those.
- Single/double-deck composition effects (a few cells) are not modeled.

**Cross-check the hints against an authoritative chart for your exact ruleset before
relying on them** — teaching a wrong move is the worst possible bug. Toggle the
advisor off via `teaching.showBasicStrategyHints` in the config any time.

## Card counting

With a depleting shoe (not a continuous shuffler), the app shows a **live Hi-Lo
readout** under the top bar: the **running count**, the **true count** (running ÷
decks remaining), and how many decks are left. It updates as each card appears and
counts the dealer's hole card **only once it's revealed** — exactly what you'd see at
the table — accumulating across rounds until the shoe reshuffles.

Hi-Lo tags are **2–6 → +1, 7–9 → 0, 10–A → −1**; the value shows green when the count
favors the player and red when it favors the house. Toggle it via
`teaching.showCardCounting` (and `teaching.showTrueCount`) in the config; it's hidden
when `shoe.continuousShuffle` is on. Only Hi-Lo is implemented — the startup
capability guard warns if another `teaching.countingSystem` is configured and falls
back to Hi-Lo.

## Betting simulator

Tap **📊** in the top bar to open the simulator. Pick a **betting system**
(Martingale or a flat-bet control), how many **sessions** to run, and how many
**hands** each, then **Run**. It plays thousands of sessions headlessly through the
real game engine — every hand by basic strategy, the system only choosing the bet —
and charts the **distribution of final profit/loss**, with summary stats (mean,
median, ruin rate, best/worst).

It makes the Martingale trap vivid: *most* sessions win a little (a positive
**median**), but a large share **bust the whole bankroll** (the spike at the left,
e.g. −$500), so the **mean** still loses — and worse than flat betting. The table
maximum (`table.maxBet`) caps the doubling. Each run is a fresh Monte Carlo draw, so
numbers vary run to run. It simulates your configured rules, shown in the header.

## Installing on a phone (Phase 6)

A PWA's install + offline features require **HTTPS** (only `localhost` is exempt),
so the app gets deployed to a free static host (GitHub Pages / Netlify / Cloudflare
Pages) in Phase 6. Once hosted:

- **Android Chrome:** menu → *Install app* / *Add to Home screen*.
- **iOS Safari:** *Share* → *Add to Home Screen* (manual — there is no auto-prompt).

This phase, installability + offline are verified on the desktop (Chrome DevTools /
the production `preview` server): the service worker registers and precaches the
full app shell.

## Testing & correctness

`npm test` covers the engine's edge cases (multi-ace soft totals, blackjack vs. a
plain 21, split aces, double-after-split, bust/push, dealer H17 vs. S17, peek, 3:2 /
6:5 payouts) and the strategy engine (dealer odds + the decision table vs. canonical
anchors). Money is tracked in **integer cents** to avoid floating-point drift.

> The strategy advisor is **computed and validated**, but still **cross-check it
> against an authoritative chart** for your exact ruleset before relying on the
> hints — see [Strategy hints](#strategy-hints).
