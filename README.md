# Blackjack Trainer

An **offline, config-driven blackjack game** built as an installable PWA, optimized
for mobile (Android Chrome; iOS Safari supported). Personal learning tool — chips
only, no real money. The full vision and phase plan live in
[`blackjack-trainer-spec.md`](blackjack-trainer-spec.md).

**Status: Phases 1–2 complete** — a correct, unit-tested game of blackjack with a
mobile-first UI, SVG cards & chips, deal/chip/shuffle animations, synthesized
sound, and saved progress (bankroll + settings persist across sessions).
Teaching/strategy hints, card counting, and the betting simulator are later phases
(see [Roadmap](#roadmap)).

## Quick start

Requires **Node 18+** (built with Node 24 LTS) and npm.

```bash
npm install
npm run dev        # play at http://localhost:5173
npm test           # run the engine unit tests
npm run build      # production build (PWA: manifest + service worker) -> dist/
npm run preview    # serve the production build at http://localhost:4173
npm run icons      # regenerate the placeholder app icons
```

## Changing the rules

**All blackjack rules live in one file: [`config/blackjack-rules.config.js`](config/blackjack-rules.config.js).**
It is the single source of truth — the engine reads from it and never hardcodes a
rule. Edit a value and:

- in **dev** (`npm run dev`), Vite hot-reloads instantly;
- for a **built/installed** app, the config is bundled, so run `npm run build` again.

Common knobs: number of decks, dealer **H17/S17** (`hitsSoft17`), blackjack payout
**3:2 vs 6:5** (`payouts.blackjack`), table **min/max bet**, starting bankroll, and
chip denominations.

### What the game implements

Dealing, hit / stand / **double** / **split** (including split-aces one-card and
double-after-split), **late surrender**, **insurance**, dealer play with US
**peek**, blackjack/bust/push detection, 3:2 (or 6:5) payouts, chip betting, and
bankroll tracking.

The following config options are **not implemented yet**. The app runs a capability
guard at startup and **warns in the console (and on-screen) if you enable any of
them**, rather than silently mis-playing:

| Config option | Status |
| --- | --- |
| `player.surrender: 'early'` | falls back to late surrender |
| `shoe.continuousShuffle` | falls back to penetration-based reshuffle |
| `dealer.peeksForBlackjack: false` (European) | falls back to US peek |
| `player.resplitAces`, `player.hitSplitAces` | split aces always get one card |

The **bankroll and mute setting persist** across sessions via IndexedDB (an
interrupted hand is voided, not charged, on reload). Use the topbar **↺** to reset
to the starting bankroll.

## Project layout

```
config/   blackjack-rules.config.js   the single source of truth for the rules
src/
  engine/      pure, unit-tested game logic — no DOM:
               cards · shoe (Fisher-Yates) · hand · dealer · settlement ·
               game (state machine) · money (integer cents) · validateRules (guard)
  assets/      the swappable look + sound: theme.js (palette) · svg.js (cards/chips)
               · sound.js (Web Audio effects)
  persistence/ store.js (tiny IndexedDB key/value) · persist.js (bankroll + settings)
  ui/          DOM rendering (render.js) + input/audio wiring (controls.js)
  main.js      bootstrap: config -> guard -> load -> game -> mount
tests/     vitest engine tests (one file per module)
scripts/   generate-icons.mjs — placeholder icon generator
public/icons/  app icons (simple placeholders)
```

The engine is **pure and rules-injected** (functions take the rules object), so it
is deterministic and testable across rule variants. The UI asks the engine for
action legality (`canHit`/`canDouble`/`canSplit`) and never re-derives rules.

## Changing art & sounds

The look and sound live in **`src/assets/`** so they're easy to re-skin in one
place: `theme.js` (suit colors, card + chip palette), `svg.js` (the programmatic
card / chip art), and `sound.js` (the synthesized Web Audio effects). App icons are
generated by `scripts/generate-icons.mjs` into `public/icons/` (`npm run icons`).
Animations respect `prefers-reduced-motion`, and sound has an in-app mute toggle.

## Installing on a phone (Phase 6)

A PWA's install + offline features require **HTTPS** (only `localhost` is exempt),
so the app gets deployed to a free static host (GitHub Pages / Netlify / Cloudflare
Pages) in Phase 6. Once hosted:

- **Android Chrome:** menu → *Install app* / *Add to Home screen*.
- **iOS Safari:** *Share* → *Add to Home Screen* (manual — there is no auto-prompt).

This phase, installability + offline are verified on the desktop (Chrome DevTools /
the production `preview` server): the service worker registers and precaches the
full app shell.

## Testing & correctness

`npm test` covers the engine's edge cases: multi-ace soft totals, blackjack vs. a
plain 21, split aces (one card each), double-after-split, bust/push, dealer H17 vs.
S17, peek, and 3:2 / 6:5 payouts. Money is tracked in **integer cents** to avoid
floating-point drift.

> The basic-strategy advisor is a **Phase 3** feature and is intentionally **not**
> in the MVP, so there is no risk of the app teaching a wrong move yet. When it is
> added, cross-check it against an authoritative chart for the exact ruleset before
> relying on its hints.
